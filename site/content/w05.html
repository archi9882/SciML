這週只回答一個問題。理論、例題、變化題都是為了回答它，週末你要用自己的話寫出答案。

為什麼這週重要

穩定不等於準確。一個穩定的格式可能把洪峰抹平，讓你以為是物理擴散；邊界條件寫錯，波會從不該出現的地方冒出來。審查 AI 的求解器，要能分辨「格式造成的」與「物理造成的」，並把求解器包成可重現、可批次掃描的形式。

範例在 week05/advection_burgers.py。本週審查 HydroWatch 的河道洪水演算的數值擴散與邊界條件，並用你自己的求解器換掉它；legacy/ 的 Fortran 版是對照基準。

一理論與示範

要找出數值方法的失真，需要四個觀念：對流與 CFL 數、一階 upwind 的數值擴散、Burgers 方程的激波、把求解器包成 solve(params)。

Day 11. 對流方程、upwind 與 CFL 數

名詞

對流方程：\(u_t + a\,u_x = 0\)，波形以速度 \(a\) 平移、形狀不變。

Upwind（迎風）：空間差分用水流來的那一側：\(u_j^{n+1} = u_j - C\,(u_j - u_{j-1})\)。

CFL 數 \(C = a\,\Delta t/\Delta x\)：一個時間步長，波走了幾個網格。顯式 upwind 要求 \(C \le 1\)。

範例用洪水波速 \(a = 14.7\) km/hr（推導見 docs/parameters.md），初始是寬度 1 km 的高斯波，上游端固定為 0、下游端零梯度（波自由流出）。

Day 22. 一階 upwind 的數值擴散

把 upwind 展開（修正方程分析），它實際解的方程多了一個擴散項：

\[u_t + a\,u_x = D_\text{num}\,u_{xx}, \qquad D_\text{num} = \frac{a\,\Delta x\,(1 - C)}{2}\]

高斯波的變異數 \(\sigma^2(t) = \sigma_0^2 + 2D_\text{num}\,t\)

示範：第一段輸出（\(\Delta x = 0.5\) km，\(t = 0.5\) hr）
CFL D_num [km²/hr] 峰值 變異數 預測 0.9 0.367 0.709 0.997 0.868 0.5 1.838 0.454 2.374 2.337 0.1 3.308 0.361 3.806 3.808

程式裡一個物理擴散項都沒有，波形卻被抹平：CFL 越小（步長越小），數值擴散反而越大。CFL = 0.5 時 \(D_\text{num}\) 是河道物理擴散係數 0.60 的 3 倍。模型輸出的「擴散」，大部分是格式造成的。

Day 33. Burgers 方程：對流讓波形變陡，擴散把它撐住

\(u_t + u\,u_x = \nu\,u_{xx}\)。對流項讓高的地方跑得快，波前越來越陡；擴散項（黏滯係數 \(\nu\)）限制它不要變成垂直的斷崖（激波）。激波厚度大約和 \(\nu\) 同量級，網格必須比它細，才算解出來。

示範：第二段輸出（\(t = 0.3\)，週期邊界，\(u_0 = \sin 2\pi x\)）最大梯度 \(\max|u_x|\)
nx ν=0.05 ν=0.01 ν=0.002 100 5.3 24.9 54.0 200 5.5 30.8 90.5 400 5.6 34.7 132.8 800 5.7 37.0 170.2

\(\nu = 0.05\) 時網格加密到 200 以上，結果只變動 4%，算是收斂；\(\nu = 0.002\) 時每加密一倍梯度就大幅增加，還沒收斂。數值格式自帶的黏滯會把激波抹得比物理的更厚，網格不夠細時，看到的是格式，不是 \(\nu\)。

Day 44. 把求解器包成 solve(params) → 結果

第 2 週的批次工具只會「用參數執行一支程式」。要讓數值實驗可重現，求解器本身也要能被這樣呼叫：輸入是一個參數字典，輸出是同一個字典加上指標。這樣掃描 CFL 與網格、存檔、事後回溯，都是同一個介面。

solve({"nx": 81, "cfl": 0.5}) → {"params": {...}, "peak": 0.5899, "variance_km2": 1.4219, "variance_predicted_km2": 1.4188, "d_num_km2_hr": 0.919}

二例題（完整示範）

例題

CFL = 0.5、\(\Delta x = 0.5\) km 時，峰值從 1 降到 0.454。這是格式的問題，還是物理？預測再比對。

步驟 1：列出可能的來源。程式沒有物理擴散項，所以來源只有格式本身：數值擴散（一階項），以及更高階的項（色散）與邊界、取整。

步驟 2：用公式預測，再與實測比對。變異數預測用 \(D_\text{num} = a\,\Delta x\,(1 - C)/2\)，峰值用高斯展寬 \(1/\sqrt{1 + 4Dt/w^2}\)（\(w = 1\) km）：

CFL\(D_\text{num}\)變異數：預測／實測差
0.90.3670.868 / 0.99713%
0.51.8382.337 / 2.3741.6%
0.13.3083.808 / 3.8060.1%

CFL = 0.5 時峰值預測 \(1/\sqrt{1 + 4 \times 1.838 \times 0.5} = 0.462\)，實測 0.454，差約 2%。

步驟 3：解釋。數值擴散的公式在 CFL 不大時預測得很準。CFL 接近 1 時 \(D_\text{num}\) 很小，其他被忽略的項（色散、時間步取整）變得相對重要，誤差變大。

步驟 4：下結論。0.454 的峰值幾乎全是格式造成的。如果模型再加上物理擴散 \(D = 0.60\)，總擴散只增加約 33%（\(1.84 \to 2.44\)），物理的部分被格式淹沒，看輸出無法分辨。結論的寫法：一階 upwind 在 CFL 0.5、\(\Delta x\) 0.5 km 時，數值擴散是物理擴散的 3 倍；要用模型的擴散去推論物理，必須先把格式的部分扣掉，或換用更高階的格式與更細的網格。

這個例題教的方法

先用理論預測失真的大小，再跟輸出比對。失真能被預測，才能被扣除、被設計掉。

Day 4變化 1：找出沒收斂的條件

用第二段輸出（Burgers 最大梯度），判斷 \(\nu = 0.05\)、0.01、0.002 各自要多細的網格才算收斂？用「相鄰兩次加密，變動小於 5%」當標準，並估計 \(\nu = 0.002\) 大約要多少格。

提示

激波厚度約與 \(\nu\) 同量級，網格間距要比它小得多。\(\nu = 0.002\) 時 nx = 800 的 \(\Delta x\) 是 0.00125。

參考答案

\(\nu = 0.05\)：200 格之後的變動 2% 與 2%，已收斂；\(\nu = 0.01\)：400 到 800 格仍變動 6.6%，還沒收斂；\(\nu = 0.002\)：400 到 800 格變動 28%，離收斂很遠，需要上千格以上。結論：\(\nu\) 越小，需要的網格越細，一個沒有收斂測試的 Burgers 結果不能信。

變化 2：讓 AI 把求解器包成 solve(params) 並批次掃描

請 AI 寫一支批次程式，掃描 nx ∈ {21, 41, 81} 與 cfl ∈ {0.2, 0.5, 0.9}，輸出一張表。先寫兩個檢查再執行：每組結果的變異數要接近公式預測（CFL ≤ 0.5 時差在 3% 以內）；同樣的參數執行兩次，結果要完全一樣。

提示

第 2 週例題的老問題也會出現：新舊結果混在一起、參數組合重複。

Day 5變化 3：審查成品，並換成你自己的求解器

審查 HydroWatch 的 routing.py：算出它的 \(D_\text{num}\)，與 \(D = 0.60\) 比較；檢查邊界條件（上游端、下游端各是什麼）。然後用 legacy/transport.f90 的輸出（legacy/reference_output.txt）當對照基準。記進 audit_log.md。

接著寫你自己的 solve(params)，邊界條件用開放邊界（下游端零梯度、上游端固定），結果要和 Fortran 參考一致，再換進 routing.py，確認 python -m hydrowatch run 與 pytest 仍能跑。

提示

把邊界條件、格點數、步數都和 Fortran 版對齊，只比較 peak 與 sum 兩個數字就夠判斷。
