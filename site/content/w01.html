這週在練什麼

職缺要求的核心能力是：AI 給出一段數值程式時，你能判斷它哪裡悄悄錯了。這需要先能讀懂程式，知道每個數字的單位、每一段在做什麼、改哪裡會影響什麼。

這週的素材是一條合成潮位：用公式產生 60 天、每小時一筆的水位，再做統計與畫圖。用合成資料的原因是真值已知。程式算出來的數字對不對，可以直接拿理論值檢查。

Must Have 3「GAI 協作與驗證」：識別數值計算中的錯誤。Should Have「資料分析」：統計結果是否可信。

Day 2物理背景：潮汐是幾個正弦波相加

潮汐分析把水位拆成好幾個固定頻率的正弦波，每一個叫做一個分潮，對應一種天體的週期運動。這支程式只用最主要的兩個。

名詞

M2（主太陰半日潮）：月球引力造成，週期 12.42 小時。「半日」指一天約漲退兩次；12.42 小時是半個太陰日（月球相對地球轉一圈約 24.84 小時）。通常是最強的分潮。

S2（主太陽半日潮）：同樣的機制，換成太陽。太陽很遠，潮汐效應較弱。週期正好 12.00 小時。

水位寫成公式：

η(t) = MSL + A_M2·cos(2πt / 12.42) + A_S2·cos(2πt / 12.00) + 雜訊 （t 的單位：小時）

兩個週期很接近但不相等，所以兩個波會慢慢錯開：同向時互相加強，叫大潮；反向時互相抵消，叫小潮。從大潮到下一次大潮的時間，就是兩個頻率的差：

大小潮週期 = 1 / |1/12.42 − 1/12.00| ≈ 354.9 小時 ≈ 14.79 天 大潮潮差 = 2 × (A_M2 + A_S2) 小潮潮差 = 2 × |A_M2 − A_S2|
先預測再驗證（Day 2 Q2）

把 S2 振幅拉到 1.00，跟 M2 一樣大。先用上面的公式算小潮潮差，再拉動滑桿確認，最後改程式的 S2_AMP 執行，看程式印出的「最小潮差」。三個數字應該一致，只差雜訊。

產生資料：一次算完整條陣列

你已經把原本的 make_tide() 拆成兩個函式，分潮可以單獨拿來畫圖，這個拆法很好。

week01/tide_example.py
def make_constituents(start: str, days: int, freq: str) -> pd.DataFrame:
    n = days * 24
    time = pd.date_range(start=start, periods=n, freq=freq)
    t = np.arange(n, dtype=float)          # [0, 1, 2, ..., n-1]
    m2 = M2_AMP * np.cos(2 * np.pi * t / M2_PERIOD)
    s2 = S2_AMP * np.cos(2 * np.pi * t / S2_PERIOD)
    return pd.DataFrame({"m2": m2, "s2": s2}, index=time)

def make_tide(start: str, days: int, freq: str, seed: int) -> pd.Series:
    rng = np.random.default_rng(seed)
    comp = make_constituents(start, days, freq)
    noise = rng.normal(0.0, NOISE_STD, size=len(comp))
    eta = MEAN_SEA_LEVEL + comp["m2"] + comp["s2"] + noise
    return pd.Series(eta.values, index=comp.index, name="eta_m")

np.cos(...) 一次處理整條陣列，不用迴圈，這叫向量化。pd.date_range 產生時間軸，當作資料的索引，之後才能「依日期分組」。

陷阱一：取樣頻率改了，t 就不是小時（Day 2 Q1）

t = np.arange(n) 只是 0, 1, 2, …。它代表「小時」，完全是因為兩個巧合同時成立：取樣間隔剛好 1 小時，而且公式裡的週期 12.42 用的單位是小時。

把 FREQ 改成 "30min"，每一步實際只過 0.5 小時，但 t 還是每步加 1。公式以為過了 1 小時，波形就跑快一倍，週期看起來只剩 6.21 小時。還有第二個問題：n = days * 24 也是寫死的，30 分鐘取樣時 60 天應該有 2880 筆，程式只產生 1440 筆，等於只模擬了 30 天。

為什麼這種錯很危險

程式不會報錯，圖也畫得出來，只是數值錯了。這正是職缺說的「數值悄悄飄掉」。修正方式是用時間軸本身算出實際經過的小時數：

t_hours = (time - time[0]) / pd.Timedelta(hours=1)   # 不管 freq 是什麼，單位都是小時

第 2 週的 tide_cli.py 就是用這個寫法，你會在那裡驗證它。

陷阱二：seed 控制的是哪些東西（Day 2 Q3）

你用 seed_check.py 實際比對過了：只有分潮 comp 不受 seed 影響，其他輸出都變了。原因是分潮由公式算出，雜訊由亂數產生器產生，seed 決定的只是那串亂數。

固定 seed 的目的是可重現：同一組參數每次產生完全相同的雜訊。之後比較「改了某個參數前後」的差異時，才能確定差異來自參數，而不是雜訊剛好不同。第 5 週做批次實驗時，seed 會變成要記錄在設定檔裡的一個參數。

Day 3pandas 統計：依日期分組

resample("D") 依日期把資料分組，跟 Excel 樞紐分析的「依日期彙總」類似。分組之後，.agg() 對每一組算指定的統計量。

week01/tide_example.py
def daily_stats(eta: pd.Series) -> pd.DataFrame:
    daily = eta.resample("D").agg(["max", "min", "mean"])
    daily["range"] = daily["max"] - daily["min"]
    return daily
先預測再寫（Day 3 Q1）

一天幾次高潮？一天 24 小時，M2 週期 12.42 小時，24 ÷ 12.42 ≈ 1.93。所以大多數日子有 2 次，大約每兩週會有一天只有 1 次。寫完 high_count 後，檢查結果是否符合這個預期。

用理論檢查結果（Day 3 Q2）

正弦波在很多個週期內平均為 0，所以每月平均水位應該很接近 MEAN_SEA_LEVEL（0.20 m）。如果差很多，先懷疑程式，再懷疑資料。

Day 4畫一張能放進報告的圖

圖是給別人看的結論，不是程式的副產品。這份檢查清單之後每週都會用：

  • 每個軸都有名稱與單位
  • 標題說明這張圖在比較什麼
  • 有理論值或基準線可以對照
  • 不看程式碼，同事 10 秒內看得懂重點

第三點最常被忽略。在潮差圖上加兩條水平虛線，標出理論的大潮與小潮潮差，讀者一眼就能看出模擬是否合理：

ax2.axhline(2 * (M2_AMP + S2_AMP), ls="--", color="gray", label="theory spring range")
ax2.axhline(2 * abs(M2_AMP - S2_AMP), ls=":", color="gray", label="theory neap range")

重點在第 3 小題：方法在什麼條件下會失敗。先用下面的動畫建立直覺，再回到自己的程式驗證。

雜訊一大，相鄰兩筆的高低就由雜訊決定，一個真正的高潮附近會冒出好幾個假峰值。兩種常見解法：

  • 先平滑：用移動平均壓掉高頻雜訊。代價是峰值的高度與時間會被拉偏。
  • 設定最小間隔：兩次高潮至少相隔幾小時。這是用物理知識（半日潮週期約 12.4 小時）約束演算法。
