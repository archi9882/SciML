# 職缺技能盤點：安瑟樂威（能源公司）

**狀態**：尚未決定是否調整 20 週計畫。本文件只是技能盤點，供之後比較其他職缺、或決定調整方向時參考。
**盤點日期**：2026-11-02

## 職缺核心主張

多源異質資料要變成可靠的決策依據，涉及數值模擬、空間資訊技術、資料管線、self-hosted 平台架構。GAI 是日常工具，但真正要的是「AI 出錯時能判斷錯在哪」的能力——數值飄掉、物理假設站不住、架構埋地雷。

## Must Have（核心必備，三項都要做過，不要求資深）

職缺描述這三項是同一條決策鏈：**物理判斷設計實驗 → 基礎設施跑起來 → GAI 加速，但你負責抓錯**。

| 項目 | 具體要求 | 期待深度 |
|---|---|---|
| 數值模擬與物理判斷 | 做過模擬、懂背後物理意義 | 判斷 physics-based／data-driven ML／hybrid 怎麼選；哪些環節對誤差敏感、哪些簡化不可接受，據此設計驗證流程 |
| 自有基礎建設架構 | Linux 下設計可由 AI/自動化維運的 PaaS/CaaS/FaaS | 判斷該不該 self-host、架構能否撐資料量成長 10 倍、AI 生成的 manifest/config 的地雷——架構決策者，不是維運操作員 |
| 生成式 AI 協作與驗證 | 會用 GAI 輔助研發 | 設計 prompt strategy 拆解科學問題、識別數值計算中的 hallucination、判斷 AI 建議的演算法在物理約束下是否成立 |

## Should Have（領域類至少 1 項＋工程類至少 1 項）

**領域類**

| 項目 | 內容 | 期待深度 |
|---|---|---|
| 空間資訊技術（非視覺化導向） | 多格式空間資料、計算幾何（Voronoi、Delaunay、mesh generation）、拓撲運算 | 不用自己刻演算法，但要能驗算 AI 生成的空間分割／座標轉換的拓撲與投影是否正確 |
| 資料分析 | 統計推論、視覺化溝通、資料品質監控、實驗設計與因果推論 | 能抓假設檢定前提是否成立、視覺化是否誤導、因果方向有沒有搞反 |

**工程類**

| 項目 | 內容 | 期待深度 |
|---|---|---|
| Python ETL＋數值計算 | 異質多源資料的 ETL；統計方法正確應用 | 判斷 AI 生成的 pipeline 哪裡會悄悄出錯 |
| REST API 開發 | 把內部運算（資料處理、模型推論、格網查詢）包成穩定服務端點 | 介面設計經得起需求演化、異常處理涵蓋真實邊界情境 |

## 對照現有 20 週計畫（PLAN.md）

**已有基礎、方向一致：**
- 數值模擬與物理判斷——水文背景＋計畫第 3–9 週（FDM／PINN）直接對應。
- 資料分析——計畫已有統計、實驗設計練習（NSGA-II、批次實驗）。
- GAI 協作與驗證——是整個計畫的核心訓練方式，但目前情境偏「ML 研究」，不是「架構／pipeline／legacy code 審查」。
- ML 模型訓練（Nice to Have 第 1 項的一部分）——PINN/FNO/Kaggle 練習大致涵蓋訓練策略與特徵工程。

**目前計畫完全沒有，屬於新增缺口：**
- 自有基礎建設架構（Linux 服務架構、PaaS/CaaS/FaaS、容器化）
- 空間資訊技術（計算幾何、拓撲運算的驗算角度，不是流體物理）
- REST API 開發
- ETL 工程（異質多源、多格式頻率品質的設計訓練）
- 特定情境程式語言的 debug 能力（Fortran/C/C++/Rust/Go，HPC 平行化 trade-off）
- MLOps 工具鏈（實驗追蹤、流程編排、版本控制、模型監控）
- 空間內插與地理統計（Kriging 等，理論依據與假設的挑選邏輯）
- 推論加速、Edge 部署、可解釋 AI、CI/CD、模型服務化

粗估：若要完整補齊第 3 塊（工程/架構）與空間方法，大約需要再加 4–6 週的新內容，目前 20 週計畫完全沒有涵蓋。
