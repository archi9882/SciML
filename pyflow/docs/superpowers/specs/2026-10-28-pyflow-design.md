日期：2026-10-28
狀態：第一版 demo 已實作（見本資料夾外的程式碼）。本文記錄定稿的決策與理由。

## 1. 目標

使用者把任意 .py 檔拖曳進網頁，在搜尋欄輸入變數或函式名稱，即以圖形顯示其前後傳遞關係。
作品公開在 GitHub，訪客不需安裝即可試用。

## 3. 圖的資料模型

節點 id 規則：

- `fn:<qualname>`：函式、方法、類別（例：`fn:Cart.add`）；模組層級程式碼為 `fn:<module>`
- `var:<scope>:<name>`：變數與參數（例：`var:main:data`）；同名不同作用域即為不同節點
- `ext:<dotted name>`：外部呼叫（例：`ext:np.mean`）

邊的種類：

| kind | 家族 | 方向 |
|---|---|---|
| call | 呼叫 | 呼叫者 -> 被呼叫者 |
| assign | 資料 | 來源變數 -> 目標變數 |
| arg | 資料 | 引數 -> 參數，或引數 -> 外部呼叫 |
| return | 資料 | 變數 -> 所屬函式 |
| result | 資料 | 函式 -> 接收回傳值的變數或參數 |

關鍵設計：

1. **外部節點只進不出。** `y = len(x)` 畫成 `x -> len`（引數）與 `x -> y`（穿透），
   而不是 `x -> len -> y`；否則所有用到 `len` 的變數會被錯誤地連在一起。
2. **鄰域走訪不跨家族。** 經由資料流抵達的函式（代表它的回傳值），不再沿呼叫邊展開；
   反之亦然。否則查一個變數會牽出所有呼叫者。
3. **兩階段分析。** 先建立作用域並收集每個作用域綁定的名稱（Python 在編譯期決定區域變數），
   再依序走訪敘述產生邊。

## 4. 與交接文件不同的判斷（實作時決定）

- **全域與閉包變數的「讀取」有連線。** 交接文件建議全域變數標示為未支援。實作時發現讀取模組常數
  （如 `STOP_WORDS`）非常常見，標示為未支援會產生大量雜訊，且讀取的解析是確定的。
  因此改為：讀取會連到外層變數；只有透過 `global`／`nonlocal` 重新綁定時才列為未分析。
- **方法呼叫的簡易型別推論。** `cart = Cart(...)` 或參數註記 `p: Product` 時，
  `cart.add()` 會解析到 `Cart.add`。不追蹤繼承。
- **dataclass 建構子。** 沒有 `__init__` 的類別，以有型別註記的類別屬性作為建構子參數。

見 README 的「Limits」章節：單檔、不區分呼叫情境、不追蹤別名、控制流程不畫成資料流、不追蹤繼承。
