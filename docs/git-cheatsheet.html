Git 速查手冊

適用於 sciml repo，遠端 origin，主分支 main。點指令旁的「複製」即可貼到終端機。

原則 每日 新任務 分支 提交 撤銷 同步 查找 錯誤 檢查 救急

找不到符合的內容。

核心原則

1. main 永遠可執行

不直接在 main 上開發，所有變更透過分支與合併完成。

2. 小步提交

一個 commit 只做一件事，訊息要能說明為什麼改。

3. 先看再做

改動狀態的指令之前，先跑 git status。

4. 不改寫已推送的歷史

已推送的 commit 不做 rebase 或 reset 後強制推送。

5. 不提交產物

資料、輸出圖表、模型權重由 .gitignore 排除。

每日必備

git status查看狀態
git diff --staged查看已暫存的變更（未暫存用 git diff）
git log --oneline --graph --decorate -20查看最近 20 筆歷史
git pull --rebase同步遠端最新內容
git push推送目前分支
git branch -vv查看分支與追蹤關係
git remote -v查看遠端網址

開始一個新任務

  1. STEP 1

    同步最新 main

    git switch main git pull --rebase
  2. STEP 2

    建立功能分支

    git switch -c feat/w02-batch
  3. STEP 3

    逐段檢視後暫存

    git add -p
  4. STEP 4

    依格式提交

    git commit
  5. STEP 5

    第一次推送並設定追蹤

    git push -u origin feat/w02-batch
  6. STEP 6

    在 GitHub 開 Pull Request，審閱後合併到 main

分支示意與命名

main
feat/w02-batch

分支從 main 分出，完成後透過 Pull Request 合回 main。

前綴用途範例
feat/新功能或新練習feat/w02-batch-script
fix/修正錯誤fix/tide-resample
docs/文件docs/venv-guide
exp/實驗，可能丟棄exp/pinn-beta-sweep
report/失敗案例報告report/w04-failure-1

命名用小寫與連字號，不含空白與中文。

提交訊息格式（Conventional Commits）

<類型>(<範圍>): <摘要>   # 50 字內，命令式語氣

<正文：為什麼改、改了什麼，每行 72 字內>

<頁尾：關聯議題>
feat 新增功能或練習
fix 修正錯誤
docs 文件
refactor 重構，行為不變
test 測試
chore 設定與依賴

範例

feat(w02): add argparse CLI for tide batch runs Allow varying M2 amplitude and noise level from the command line. Refs: week02/exercises.md Day 3

暫存與提交

git add 檔名暫存指定檔案
git add -p逐段暫存（推薦）
git restore --staged 檔名取消暫存，檔案內容保留
git commit --amend修改最近一次 commit 訊息（僅限未推送）

撤銷與還原

安全

取消暫存

git restore --staged 檔名
無法復原

放棄未提交的修改

git restore 檔名
安全

還原已推送的 commit

新增一個反向 commit，歷史保留。

git revert 雜湊值
謹慎

撤銷最近一次 commit，保留修改

僅限未推送。

git reset --soft HEAD~1
安全

暫存未完成的工作

git stash push -m "說明"

取回：git stash pop

禁止（除非完全明白後果）

  • git push --force 推送到 main
  • 有未提交工作時執行 git reset --hard
  • 已共享的分支強制推送；必要時改用 git push --force-with-lease

同步與衝突

git pull --rebase把自己的 commit 接到遠端最新之後
git add 檔名 && git rebase --continue解完衝突後，標記為已解決並繼續
git rebase --abort放棄本次 rebase，回到開始前的狀態

衝突標記為 <<<<<<<、=======、>>>>>>>。保留正確內容並刪除標記後，再執行 git add。

查找問題

git blame 檔名查看每一行是誰、哪次 commit 改的
git log -S "關鍵字" --oneline搜尋歷史中新增或刪除該字串的 commit
git bisect start二分法找出造成錯誤的 commit（之後用 good／bad 標記）
git show 雜湊值查看某個 commit 的內容
git log main..feat/xxx --oneline列出分支上 main 沒有的 commit

常見錯誤

錯誤訊息原因解法
repository moved遠端網址已變更git remote set-url origin 新網址
rejected (non-fast-forward)遠端有你沒有的 commitgit pull --rebase 後再推送
detached HEAD直接切到某個 commitgit switch -c 新分支名 保存工作
Author identity unknown未設定使用者資訊設定 user.name 與 user.email
Permission denied (publickey)SSH 金鑰未設定改用 HTTPS，或設定 SSH 金鑰
CRLF will be replaced by LFWindows 換行差異正常警告，可忽略

一次性設定

git config --global user.name "你的名字" git config --global user.email "你的 GitHub 信箱" git config --global init.defaultBranch main git config --global pull.rebase true git config --global push.autoSetupRemote true

Windows 建議加上 git config --global core.autocrlf true；Mac/Linux 用 input。

提交前檢查清單

快速救急

不確定自己做了什麼

先看 git status 與 git log --oneline -5。

改壞了檔案

未提交：git restore 檔名。已提交：git revert。

推送被拒絕

先 git pull --rebase，再 git push。

誤刪了分支

用 git reflog 找到最後的 commit，再 git switch -c 分支名 雜湊值。

想先離開

用 git stash push -m "說明" 暫存。

清除未追蹤檔案前，先用 git clean -nd 預覽；git clean -fd 會永久刪除。
