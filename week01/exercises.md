# 第 1 週：用 AI 協作寫 Python（潮位時間序列）

**本週目標**：能「讀懂」一支 80 行的資料處理程式，知道每段在做什麼、改哪裡會影響什麼；開始用 Git 記錄自己的進度。
**每天時間**：練習 45–60 分鐘 ＋ 論文 15–20 分鐘（論文進度見追蹤頁）。
**本週論文**：Kratzert et al. (2019)，用 LSTM 做區域降雨－逕流模擬。它和本週一樣處理水文時間序列，可以看到「同樣的資料，ML 怎麼用」。

> **名詞** M2、S2 是潮汐分析中的「分潮」：潮汐訊號可拆成幾個固定頻率的正弦波之和，
> 每個分潮對應一種引起潮汐的天體週期性運動。M2（主太陰半日潮）由月球引力造成，
> 週期 12.42 小時；S2（主太陽半日潮）由太陽引力造成，週期 12.00 小時，通常較弱。
> 兩者疊加產生約 14.8 天一次的大潮／小潮循環。完整說明見 `tide_example.py` 的檔案開頭註解。

## 使用 AI 的規則（整個課程都適用）

語法可以外包，邏輯不外包。具體做法：

| 可以請 AI 做 | 自己做 |
|---|---|
| 解釋某一行語法是什麼意思 | 決定要算什麼、為什麼這樣算 |
| 查函式的參數（例如 `resample` 怎麼用） | 先**預測**結果，再執行驗證 |
| 改寫成更簡潔的寫法 | 判斷輸出合不合理（物理上對不對） |
| 找錯誤訊息的原因 | 寫 commit message（用自己的話描述改了什麼） |

好的提問範例：「這行 `eta.resample("D").agg(["max","min"])` 在做什麼？用 Excel 的概念類比給我聽，不要給我新程式碼。」

## Day 1：環境設定，先讓程式跑起來

1. 安裝 Python（建議 [Miniconda](https://docs.anaconda.com/miniconda/) 或 [uv](https://docs.astral.sh/uv/)）與 VS Code。
2. 建立環境並安裝套件：`pip install numpy pandas matplotlib`
3. 安裝 Git，在 GitHub 建一個新 repo（例如 `sciml-journey`），clone 到電腦。
4. 把 `tide_example.py` 放進 `week01/`，執行它，確認產生 `tide_overview.png`。
5. 第一次 commit：
   ```bash
   git add week01/
   git commit -m "week01: 加入潮位範例程式，可正常執行"
   git push
   ```

**完成標準**：GitHub 上看得到你的檔案與圖。

## Day 2：讀懂第 1 段（產生資料），先預測再執行

讀 `make_tide()`，然後回答（寫在 `week01/notes.md`）：

1. `t = np.arange(n)` 的 `t` 單位是什麼？如果把 `FREQ` 改成 `"30min"`，`t` 還對嗎？哪裡要跟著改？
2. **先預測再執行**：把 `S2_AMP` 改成 `1.00`（跟 M2 一樣大），小潮時潮差會變成多少？寫下預測，再跑程式驗證。
3. 把 `SEED` 改掉再跑兩次，哪些數字變了、哪些沒變？為什麼研究上要固定 seed？

> 第 1 題有陷阱：改了取樣頻率，`t` 就不再是「小時」。這種「單位跟著頻率偷偷改變」的錯誤，在實驗腳本裡很常見。

## Day 5：不靠 AI 寫一個小函式（練邏輯）

寫 `find_high_tides(eta)`：找出所有「比前一筆和後一筆都高」的時間點（局部極大值）。

1. **先用中文寫步驟**（偽代碼），再寫程式。這一題請不要讓 AI 直接寫。
2. 寫完後，用 AI 寫一個版本，比較兩者差異（例如它可能用 `scipy.signal.find_peaks`）。
3. 雜訊會讓你找到「假的高潮」嗎？試著把 `NOISE_STD` 調大到 `0.3` 看看。怎麼解決？（提示：先平滑，或設定最小間隔）

這一題的重點是第 3 小題：**方法在什麼條件下會失敗**。這就是之後「失敗案例報告」的雛形。
