# 驗證論文理解

## 核心原則

理解 = 闔上 PDF 後，能憑記憶重建論文的邏輯並說出它哪裡可能不成立。
Agent 只出題、對照、指出落差，**不代寫摘要、不先給答案**（使用者的理解必須來自自己的輸出）。

## 檔案與期限規則

1. 論文 PDF 放 `papers/input/年份_第一作者.pdf`；使用者自己讀，需查符號、資料、名詞時才請 agent 讀指定頁（每次最多 20 頁）。
2. 複製 `papers/output/TEMPLATE.md` 為同名 `.md`，填 5 行摘要、`week`、`output_started`（YYYY-MM-DD）。**21 天期限從這天起算，逾期不延長。**
3. 寫完第一版，開**新 session** 觸發本 skill（說「grill 這篇」並給檔名即可，不必貼提示詞）。
4. 每次討論後，使用者把修正寫進「Grill 之後的修正」；自認弄懂就把 `status` 改成 `done`，可提前結束。
5. `python papers/check.py` 列出待開始、進行中剩餘天數、逾期。

## 前置

1. 讀 output 的 `output_started`、`status`；超過 21 天只做總結，列出未弄懂的點，不再展開新討論。
2. 讀 PDF 與使用者的 output。output 還是空白，先請他寫完 5 行摘要。
3. 一次只問一題；答錯或含糊就用更小的問題引導，不直接講解。

## 不拖慢進度

- 單次 grill 以 30–45 分鐘為限；時間到就結算「已掌握／仍含糊」，下次接續。
- 不阻擋使用者進入下一週練習：未過關的點記進「我還不懂的地方」，與當週進度並行處理。
- 優先問會影響本週練習的點（資料、方法為何成立、結果意義），次要細節延後。

## 三階段（依序，每階段過關才進下一階段）

### 1. 拆解：還原成第一原理

- 問題、解法、影響三者濃縮成一句無術語的話（對象：非本領域同事）。
- 符號與資料：每個符號的物理意義與單位、輸入輸出維度、資料來源與訓練／驗證／測試切分。
- 圖表：先遮住作者的文字敘述，請使用者自己說出座標軸、單位、趨勢與該圖證明了什麼；再對照原文。

### 2. 壓力測試：找出會破的地方

- 隱含假設與適用範圍（例如流域、尺度、邊界條件、資料量）。
- 公平性：基準方法是否調過參？指標是否適合此問題？有無資料洩漏？有無消融實驗支撐「真正有效的是哪個部分」？
- 失敗情況：論文自承與未自承的限制；分佈外時會怎樣。
- 替代解釋：請使用者至少提出一個能解釋同一組數據的其他原因，並說明如何分辨。
- 數字：最重要的結果是多少、相對基準進步多少、差距有無超過雜訊（隨機種子、不確定度）。

### 3. 整合：放回文獻脈絡

- 這篇改變、反駁或補充了哪一條先前工作（至少點名一篇）。
- 用比喻對非專家重述一遍；再說明與自己目前 PLAN 中該週練習的關係。

## 結業關卡（闔卷測試）

使用者關掉 PDF，在空白處憑記憶寫出：問題、方法、關鍵結果（含數字）、兩個假設、一個限制、一個替代解釋。
Agent 對照 PDF，逐項標示「正確／含糊／錯誤」。**全部正確才可建議把 `status` 改成 `done`**；否則把含糊與錯誤的點寫進「我還不懂的地方」，由使用者自己填。

## 每回合結尾

列出：已掌握、仍含糊、下一題方向。並提醒使用者把修正寫進「Grill 之後的修正」（原本以為／實際上）。

## 常見錯誤

| 錯誤 | 修正 |
|---|---|
| 使用者說「大概懂了」就放行 | 一律要求關卡通過，嘴上說懂不算數 |
| Agent 見使用者卡住就直接解釋 | 縮小問題，必要時只指出「看第 X 節圖 Y」 |
| 只考細節記憶 | 重點是因果與限制，不是背數字 |
| 只讀摘要與結論就出題 | 必須讀方法與實驗段，問題要能被原文驗證 |
